## 1. Apple Liquid Glass 是什么

Apple 在 2025 年（iOS 26 / macOS 26）推出的界面材质。和以前的「毛玻璃」（只是把背后模糊掉）比，它多了三件事：

1. **折射（lensing）**：玻璃边缘像一块有厚度的凸透镜，把背后的内容往里弯。这是「像玻璃」的主要来源——
   只模糊不折射，看起来是一张半透明的纸。
2. **高光**：边缘有一圈随光源方向明暗变化的亮线，上沿最亮；在 HDR 屏上这圈光比页面上最白的白还亮。
3. **流动**：控件被按下、被经过、换选中时，玻璃像液体一样变形、流动、回弹，而不是瞬间切换。

还有一条分层原则：**玻璃只用在「控制层」**（导航、工具条、弹出菜单这些浮在内容上面的东西），
**内容本身不做成玻璃**。玻璃叠玻璃会糊成一片，字也读不清。

## 2. 网页上能做到哪一步

| 效果 | 网页上的做法 | 能不能做 |
|---|---|---|
| 模糊 + 提饱和度 | `backdrop-filter: blur() saturate()` | 现代浏览器都能 |
| 边缘折射（放大 + 模糊 + 散射 + 色散，正中原样） | `backdrop-filter` 里挂一个 SVG 滤镜 `url(#…)`：九宫格位移贴图 + 三路位移 + 按位移大小加权的模糊与乳白 | **只有 Chromium**（Chrome、Edge 及其内核的浏览器） |
| 按住浮起的透镜（标签栏那样） | 分段开关里盖在字上面的一块清玻璃，只挂折射、不模糊；脚本按住浮起、拖、橡皮筋、甩 | 折射只有 Chromium；别的浏览器按住时滑块放大一点 |
| 边缘高光环 | 渐变 + 遮罩挖出 1.2px 的环 | 都能 |
| 比白更亮的高光 | 一张带 HDR 标记的 16 位 PNG | 只在 HDR 屏 + 支持的浏览器上看得出来 |
| 流动、回弹 | 脚本里跑弹簧物理，逐帧写 `transform` | 都能 |
| 真正的三维反射（映出周围环境） | — | 做不到，也没必要 |

## 3. 一块玻璃是怎么搭的

```
宿主元素（位置、圆角、投影；background 必须透明；必须是层叠上下文）
 ├─ ::before   z-index:-1   底色 + 顶部柔光 + backdrop-filter（模糊 → 折射 → 饱和度 → 提亮）
 ├─ 内容        正常流
 └─ ::after    z-index:3    1.2px 的边缘高光环（渐变 + 遮罩挖成环）
```

- **滤镜不直接挂在宿主上，挂在 `::before`。** Chromium 里一个元素如果带 `box-shadow` 或 `outline`，
  位移滤镜的坐标原点会按「连投影在内的溢出范围」算，整张位移贴图跟着挪位，折射就错位了。
  投影留在宿主上，滤镜放在没有投影的 `::before` 上，两边互不干扰。
- **宿主的 `background` 必须透明。** 宿主的底色会画在 `::before` 下面、成为它「背后」的一部分，
  于是玻璃模糊的是自己的底色。更隐蔽的是 `<button>`：浏览器给它一层默认的浅灰底，
  同样的玻璃放在 `<button>` 上会比放在 `<div>` 上灰一截——两颗并排的玻璃胶囊一深一浅，多半是这个。
- **宿主必须是层叠上下文**（`position` + `z-index`，或 `sticky` / `fixed`）。否则 `z-index:-1` 的 `::before`
  会沉到页面底下去，被父元素的背景盖住。
- **高光环用遮罩挖**：`padding: 1.2px` + `mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0)` +
  `mask-composite: exclude`（Chromium 写 `-webkit-mask-composite: xor`）——内容区挖掉，只剩 padding 那一圈。
  环上的渐变是「上沿最亮 → 两侧渐暗 → 下沿再亮一点」：光从上方来，下沿那点亮是光在玻璃里反射到对边。

## 4. 折射：放大 + 模糊 + 散射

### 4.1 位移滤镜是什么

`feDisplacementMap` 拿一张「位移贴图」去挪另一张图的像素：输出图上的每一点 P，颜色取自原图上的
`P + scale × (贴图在 P 的颜色值 − 0.5)`。R 通道管横向、G 通道管纵向，颜色值 128（即 0.5）表示不动。

把它挂进 `backdrop-filter`（`backdrop-filter: blur(18px) url(#lgf-1) saturate(1.8)`），「原图」就是玻璃背后的内容。
**只要贴图画对了，背后的内容就按算好的方式弯曲**。难点全在贴图怎么算、算出来的结果怎么用。

### 4.2 iOS 26 的玻璃边是什么样

对着 iOS 26 标签栏的录屏逐帧看（ZeppBridge 做过这件事并改了五版，见 §11），玻璃边是三样东西叠起来的：

1. **放大**：边上那一圈里，背后的内容被拉开——字一到边上就被抻长、顺着边的弧度弯过去。
2. **模糊**：越靠边越糊；正中清清楚楚，一个像素都不重采样。
3. **散射**：玻璃边自己把光散开，泛一层很淡的乳白；外加一点色散——红绿蓝三路折得略不一样，端头泛彩边。

三样的强度都跟着「离边多近」走，一起从边上往里淡掉，没有分界线。

### 4.3 位移曲线：往里取样、越靠边越大

**平面上是圆角矩形**：每个像素折到离它最近的那个角的坐标系里，算离边多远（圆角那一格里离的是圆弧，其余离的是更近的那条直边），
同时得到边缘的**外法线方向**（圆角处从圆心指出去，直边处垂直于边）。这就是圆角矩形的有符号距离（Inigo Quilez 的公式）。

离边距离 s、边宽 b，斜面上**往里取样、越靠边位移越大**：

```
D(s) = K · b · (1 − s/b)²      K = 0.45；s ≥ b 时 D = 0
```

离边 s 的这一点，取的是更靠里 s + D(s) 处的内容。

- 取样位置 p(s) = s + D(s) 的斜率是 1 + D′(s) = 1 − 0.9 · (1 − s/b)：最外缘 0.1，往里升到 1——**边上拉开约十倍（放大）**，平滑落回原样。
- **处处 1 + D′ > 0，不折叠**：同一段内容只出现一次，边上不会有重影和镜像。（`scripts/displacement_map.py --selftest` 验的就是这一条。）
- 方向是外法线的反方向（往里）。圆角处法线从圆心指出去，所以圆角里的内容顺着圆弧弯。

**为什么不按斯涅尔定律算**（上一版的做法：凸超椭圆剖面 + 斯涅尔定律 + 恒定厚度，kube.io 那篇文章的思路）：
算出来的位移全挤在最外两三个像素里，而且在那儿 D′ < −1——**贴图折叠了**。边宽 18、隆起 16、厚度 8 时，
从边缘往里 0、1、2、3、4 px 处取到的位置是 8.9、5.6、5.0、5.1、5.5：先往回走再往前走，边上的字被画了两遍（重影 + 镜像），
而里面宽宽一圈斜面又几乎不动。物理上更「对」，看着反而不像玻璃。

**为什么不往外取样**（让边上映出玻璃外面的东西）：位移往里递减时往外取样，数学上是把更多内容挤进更窄的地方——**缩小**，
同一段字还会被画两遍。ZeppBridge 第三版这样做过，第四版改了回来。

### 4.4 编码

| 通道 | 存什么 |
|---|---|
| R / G | 往哪边取样：`R = 127.5 − nx · m · 127.5`（G 同理，用 ny），128 = 不动 |
| B | 位移大小 `m = (1 − s/b)²`：0 中间、1 最外缘。滤镜拿它当模糊、散射、「用不用折射结果」的权重 |
| A | 形状：圆角外透明（圆弧那一格 4×4 超采样算覆盖率） |

`feDisplacementMap` 的 `scale = 2 × 最外缘位移`（R − 0.5 在 ±0.5 之间）。8 位量化：最外缘位移 8px 时一级约 0.06px，看不出台阶。

### 4.5 九宫格：尺寸变了只挪，不重画

贴图切成四个角（c × c，c = max(圆角, 边宽)）+ 四条边（沿边方向处处一样，存一条 2 像素宽的图拉伸铺满），**中间不放**
（透明 = m 为 0 = 用原图）。

- 只有「角的边长 × 圆角 × 边宽」变了才画新贴图（`<canvas>` → data URL，按 2 倍密度画，高分屏上也细；最多缓存 24 套）。
- **尺寸变了只改八个 `<feImage>` 的 x / y / width / height**：拖窗口、透镜跟着项宽变宽变窄，都不用先撤掉折射。
  （上一版每个尺寸算一整张贴图，拖窗口时只能先撤掉折射、停手 140ms 再算。）
- 四条边各往角底下多伸 1px，角盖在上面：接缝处不会漏出一条不折射的细线。
- 前提是 w、h ≥ 2c——边宽夹在「短边一半减 1」以内，自然满足。
- `displacement_map.py --selftest` 会把九宫格拼回去，和整张贴图逐像素核对。

### 4.6 滤镜链

```xml
<filter id="lgf-1" color-interpolation-filters="sRGB">
  <feFlood flood-color="rgb(128,128,0)" flood-opacity="0" result="n0"/>      <!-- 透明的「不动」底 -->
  <feImage x="…" y="…" width="…" height="…" preserveAspectRatio="none" href="data:…" result="pt"/>  <!-- 九宫格八块 -->
  …
  <feMerge result="map"> n0 + 八块 </feMerge>

  <!-- 放大：红绿蓝三路，红多折 8%、蓝少折 8%（色散），各留一个通道再加回一张 -->
  <feDisplacementMap in="SourceGraphic" in2="map" scale="S×1.08" xChannelSelector="R" yChannelSelector="G" result="dR"/>
  <feColorMatrix in="dR" values="只留红" result="cR"/>   …绿、蓝同理…
  <feComposite operator="arithmetic" k2="1" k3="1" …/> ×2                       → sharp

  <feColorMatrix in="map" values="B → 透明度" result="m"/>
  <!-- 模糊：糊过的那份按 m^1.6 叠上去（集中在最外缘，不在里面留一圈发白的环） -->
  <feGaussianBlur in="sharp" result="soft"/>  + feFuncA gamma 1.6 + feComposite in   → lensed
  <!-- 散射：一层乳白按 m × 0.05 叠上去；颜色走令牌 --lg-scatter（深色底上淡一半） -->
  <feFlood style="flood-color: var(--lg-scatter)"/> + feFuncA linear + feComposite in → glowed
  <!-- 只在 m 明显的地方用折射结果（m × 12 截到 1）；按形状裁；垫在原图上面 -->
  <feComposite in="glowed" in2="rw" operator="in"/> → <feComposite in2="map" operator="in"/>
  <feMerge><feMergeNode in="SourceGraphic"/><feMergeNode in="shaped"/></feMerge>
</filter>
```

- **中间一个像素都不重采样**：位移不到最大值十二分之一的地方直接是原图。`scripts/shoot.mjs` 的折射校验把折射那一步换成
  `blur(0px)` 前后各拍一张，核对玻璃正中逐像素一样、外圈确实在弯。
- **贴图缺了不会错位**：底是透明的 128，缺哪一块那一块 m = 0，用原图。
- **边上的模糊顺带把锯齿抹掉**：位移滤镜是最近邻取样，边上拉开十倍，不糊一下就是一级级台阶。
- **`color-interpolation-filters="sRGB"` 必须写**：缺省是线性 RGB，贴图里的 128 会被换算成约 55，整片错位。
- **滤镜区域用缺省值**，不要写 `filterUnits="userSpaceOnUse"` 再给 x / y：那样坐标原点跑到别处，贴图对不上。
- **先模糊、再位移**：`blur(…) url(#…)`。反过来的话，位移出来的清晰边缘又被模糊掉，折射看不出来。
- 贴图摆放用元素的**布局尺寸**（`offsetWidth` / `offsetHeight`，不受 `transform` 影响）。

### 4.7 参数

| 玻璃 | 边宽 | 最外缘位移 | 色散 | 散射 | 边上模糊 |
|---|---|---|---|---|---|
| 弹出菜单 | 18 | 8 | 0.08 | 0.05 | 1.1 |
| 命令面板 | 24 | 11 | 0.08 | 0.05 | 1.4 |
| 底部保存条 | 14 | 6 | 0.08 | 0.05 | 0.8 |
| `data-lg-refract` 不给值 | 短边 × 0.2，夹在 10–24 | 0.45 × 边宽 | 0.08 | 0.05 | 边宽 × 0.06 |
| 悬停透镜（停稳时） | min(12, 高 × 0.32) | 0.45 × 边宽 | 0.06 | 0.05 | 高 × 0.02 |
| 分段开关浮起的透镜（§8.1） | 高 × 0.3（半高的六成） | 0.45 × 边宽 | 0.1 | 0.06 | 高 × 0.024 |

最外缘位移缺省都是 0.45 × 边宽（就是 K）；面板越大，边越宽、折得越多；小控件边要窄，不然整颗都在弯、字看着晃。
浮起的透镜斜面占半高的六成，正中约四成高原样透出——字就在它底下，色散也略重一点。

### 4.8 什么时候摆、什么时候撤

- 第一次出现、尺寸变了：立刻按此刻的尺寸摆九宫格（`ResizeObserver` 发现变化当帧就摆，不用撤）。
- 换档到 l0 / l1、或者检测到背景根（§4.10）：撤掉折射，只留模糊。
- 从页面上撤掉的玻璃：连滤镜节点一起清掉。

### 4.9 只有 Chromium 能折射，怎么判断

`CSS.supports('backdrop-filter', 'url(#x)')` **会说谎**：Safari、Firefox 也回答支持，然后静默丢掉整条声明——
连模糊都没了。所以按浏览器品牌判断：有 `navigator.userAgentData` 就看 `brands` 里有没有 `Chromium`，
没有就看 UA 里的 `Chrome/版本号 ≥ 90`（排除旧 Edge）。非 Chromium 直接落到只模糊的一档。

### 4.10 隔着背景根：不折射

玻璃自己或祖先带 `filter` / `backdrop-filter` / `mask` / `clip-path` / `mix-blend-mode` 时，它的 `backdrop-filter`
只看得见那个祖先里面的东西（§10）。只模糊的话无非糊的是一小块；**挂的是 `url()` 位移滤镜时，Chromium 的输出还会把原图换掉——
浮起来是一块发暗的方块**（ZeppBridge 2026-10 实测）。
所以每次摆折射之前，脚本顺着祖先往上查一遍，有就不开折射、只留模糊。透明度不算：页面切换的淡入淡出会误判，
而它只让玻璃暂时采不到背景，不出方块。要在这种容器里用浮起的透镜，把容器的毛玻璃挪到垫在底下的一层（伪元素）上——
`.lg-glass` 本来就是这么搭的（§3），所以侧栏、工具条里的分段开关照样能折射。

## 5. 高光与 HDR

### 5.1 普通高光

- 边缘高光环（§3）。
- 顶部柔光：左上角一团径向渐变，像顶灯打在玻璃上。
- 指尖光：玻璃按钮悬停时，一团 90px 的径向光跟着指针走（脚本把指针位置写进 `--mx` / `--my`）；
  没有脚本时光停在上方正中。蓝 / 红按钮上是白光；**白按钮上要带一点主色**——白光打在白按钮上等于没打。

### 5.2 HDR 高光：比白更亮

HDR 屏能显示比「页面白」更亮的颜色，多出来的那部分叫**亮度余量**。Apple 在 HDR 屏上让玻璃高光用的就是这部分余量，
看起来像真的反了一道光。网页上能稳定用到这部分余量的办法是**图片**：

- 一张 96×12 的 16 位 RGBA PNG，带 `cICP` 块 `09 10 00 01`：原色 BT.2020（9）、传递函数 PQ（16）、矩阵 0、全范围 1。
  这是 PNG 第三版标准里标记 HDR 的方式。
- 颜色按 PQ 曲线编码到「参考白 203 尼特 × 3」≈ 609 尼特；alpha 是普通的直通 alpha（不要预乘）。
- 普通屏上浏览器把它压成白色；HDR 屏上它比页面最白的白还亮。
- 只在 l3 档（HDR 屏 + Chromium + 完整）插进去，样式表里再用 `@media (dynamic-range: high)` 把一次关——普通屏上一个像素都不画。
- 为什么不用 CSS 颜色：`color(rec2100-pq …)` 这类写法各家支持还很零碎，图片的路子最稳。
- `scripts/hdr_png.py` 生成这张图，`--verify` 核对脚本里内嵌的那张。

## 6. 动效：弹簧

位置、大小、透明度、按下的程度各是一根弹簧。参数照 Apple「时长 + 回弹」的换算（SwiftUI `Spring(duration:bounce:)`）：

```
刚度 k = (2π / 时长)²
阻尼 c = 4π × (1 − 回弹) / 时长
加速度 = −k × (当前 − 目标) − c × 速度
```

| 弹簧 | 时长 | 回弹 |
|---|---|---|
| 透镜位置与大小 | 0.38s | 0.22 |
| 透镜淡入淡出 | 0.30s | 0 |
| 按下 | 0.26s | 0.35 |
| 滑块前沿 / 后沿 / 同向 | 0.30 / 0.52 / 0.42s | 0.26 / 0.16 / 0.18 |
| 分段开关浮起 / 落下（§8.1） | 0.38 / 0.26s | 0.3 / 0 |
| 橡皮筋弹回（§8.1） | 0.50s | 0.5（冲过头压扁一下再停） |
| 拖动时滑块追手指（§8.1） | 0.12s | 0 |
| 浮着飞（§8.1，两条边同一根） | 0.40s | 0.28 |

- 积分用半隐式欧拉（先更新速度、再用新速度更新位置），每帧步长夹在 4–34ms（切后台回来那一帧不会飞出去），
  **一帧再拆成不超过 4ms 的小步**：刚度高的弹簧（拖动时追手指那根，0.12s）在一步 34ms 的慢帧里会发散——
  无头浏览器里实测一下飞出去四百多万像素。
- **换目标时保留速度**：鼠标中途改道，透镜顺势拐过去，不会先停一下再走。
- 所有弹簧共用一个 `requestAnimationFrame` 循环，都停了循环就停，不空转。
- CSS 过渡（按钮浮起、箭头旋转）用 `cubic-bezier(.3, 1.6, .5, 1)` 这类「冲过头再回来」的曲线，和弹簧一个性格。

## 7. 透镜

悬停与键盘焦点统一成**一颗清玻璃透镜**：每块面板里一颗，从一项移到另一项时它流过去。

- **垫在字底下**（照 iPadOS 指针的「高亮底板」）：层次是「面板玻璃 → 选中滑块（z 0）→ 透镜（z 1）→ 字（z 2）」。
  透镜盖在字上面的话，它的高光环会从字上划过去，上下移动时字在闪。
- **形变**：沿运动方向拉长 `min(12%, |纵向速度| / 3800)`、横向 `min(8%, |横向速度| / 5200)`，
  垂直方向按 `1 / (1 + 0.6 × 另一向)` 收窄，大致保面积。鼠标比手指收敛，上限比触屏小。
- **出现**：从指针所在位置铺开（宽 55%、高 70% 的一滴），长成胶囊；同时从 86% 长到 100%。
- **消失**：离开面板后等 0.15s 再撤——手不会完全静止，擦边出去又回来时不闪。项之间的缝里透镜留在原处。
- **放大**：被盖住的项按**被盖住的比例**放大，透镜从 A 滑到 B 的路上 A 慢慢缩回、B 慢慢放大，像水滴从一项流到下一项。
  窄项 3–5%，侧栏菜单项 2.5%（图标再多 8%），宽列表项 ≤ 1.5%（放大以中心为原点，500px 宽放大 2% 左边的字就跳 5px），整行 0。
- **跟手视差**：指针下那一项朝指针挪 1.5px，透镜朝指针偏 2px（纵向减半）。
- **按下**：横向鼓 6%、纵向压 9%，那一项缩 3.5%，松手回弹，像按一块果冻；透镜里的光圈跟着放大。
  **按像素封顶**：透镜最多鼓 12px、那一项最多缩 6px——宽的项（命令面板 500px）按比例鼓，一按就顶出面板，左边的字还会跳好几个像素。
- **停稳才折射**：悬停透镜一动就在变形（水滴形、按下的果冻），而**会折射的元素绝不能缩放**——一缩放，
  透过它的东西就被重采样得发糊，贴图也对不上，会在字上划出一道缝。所以折射层只在停稳（位置误差 < 0.5px、速度很小、
  完全显现、没在按）之后，按那一刻的尺寸摆好九宫格，0.24s 淡入；一动就撤。（分段开关浮起的透镜反过来：它只平移、不变形，
  所以一路都在折射，见 §8.1。）
- **落在选中项上**：底色退到几乎透明，只剩高光环和一团更亮的跟手光，不把蓝色洗白；也不开折射——
  位移滤镜是最近邻取样，会把选中项的硬边折出锯齿。
- **整行形态**（表格行）：垫一块亮板，**指尖光照样跟着指针走**（和按钮、菜单项同一套悬停动作；光用白按钮那一份，
  浅色带一点主色，压扁成一道竖着的光）；不放大、不折射、不跟手位移。按下不往外鼓、往里收一点（≤ 8px × 3px）——
  行占满整张表，往外鼓就被表格裁掉、圆角也没了。光只在指针在的时候亮：键盘走到这一行时光会停在正中，
  宽行正中一团光像污渍（第一版就是因为这个把整行的光整个去掉了，结果和别处不一致，见 design-decisions.md 第九轮）。
- **键盘**：`:focus-visible` 的焦点也让透镜流过去；鼠标点出来的焦点不触发（鼠标本来就在那儿）。焦点环照旧画。
- **滚动容器里关在内容范围内**：面板是滚动容器（表格外框、侧栏菜单、命令面板列表）时，透镜和滑块每一帧画出来的外框
  都挪回内容范围里。伸出去一个像素滚动尺寸就被撑大：表格最后一行透镜回弹往下多冲 1px，竖滚动条一出来又挤出横滚动条，白条一闪。
  内容范围量 `scrollWidth` / `scrollHeight` **再往里让 1px**：这两个数是取过整的（真内容 439.69px 读出来 440），贴着它画，
  2 倍屏上多出的零点几像素就是一整个物理像素。放不下时（整行宽的透镜稍一放大）收宽高、不动缩放；整行透镜松手的回弹不往外鼓。
  宽度写成 `min(算好的宽度, 内容区宽 − 左边位置 − 1px)`，竖滚动条一冒出来同一次排版里就跟着变窄（不然它把横滚动条撑出来，
  两条互相撑着不走）；面板内容区一变（`ResizeObserver`，滚动条进出也算）就重量。见 pitfalls.md #41。
  **量之前先把自己插进去的透镜、滑块、浮起的透镜藏起来**（`display: none`，量完放回）：
  内容变短时它们还停在原处（表格筛完只剩两行，透镜还在原来第十行那儿），带着它们量，量到的就是被它们撑大的范围。
  透镜**淡完以后缩成 0 × 0 停在左上角**——看不见的元素照样占滚动范围；页面一变，亮着的、正在淡出的透镜都按新的范围再关一次。

## 8. 液态滑块

选中项底下那一块：侧栏选中页（蓝 / 危险页红）、分段开关（白）、命令面板光标（主色浅玻璃）。

- **两条边分开走**：往下移时下沿是前沿、用快弹簧（0.30s）先到，上沿是后沿、用慢弹簧（0.52s）后到；
  中途被拉长、落定时回弹。横向同理。这就是「液态」——一块东西被拽过去，而不是一个框瞬移过去。
- **拉长有上限**：最多比落点那一项长 44px（横向 56px），超过就让后沿被前沿拽着走。不设上限的话，
  从第一项跳到最后一项，中途是一根几百像素的蓝柱子。
- **换色**：蓝变红是两层叠着、红的那层 0.25s 淡入——渐变没法直接过渡。
- **直接跳、不演动画**的情况：第一次出现、容器宽度变了（侧栏折叠 / 展开）、减少动态效果、精简档。
- **状态存在宿主上**：列表每按一次方向键整片重画（`innerHTML`）也没关系，新建的滑块元素从原来的位置接着滑，看不出重画过。
- 有滑块时选中项自己的底色清掉（`[data-lg-slider-on]` 下的选中项 `background: transparent`）；
  没有脚本时选中项自己画底色——退路是现成的。

### 8.1 分段开关：按住浮起、拖、橡皮筋、甩

照 iOS 26 的标签栏（ZeppBridge 第五版逐帧对过）。分段开关的滑块平时是一块平的白胶囊，被按住时**浮起成一块清玻璃透镜**：

- **浮起**：按住任意一项，平胶囊一边放大到透镜的大小、一边化开；同一时刻透镜的边（一圈极淡的描边 + 浮起的影子 +
  左上 / 右下两道斜对角高光）从平胶囊的大小长出来，里面的折射淡入——看上去是同一块玻璃浮起来。浮起带一点回弹（0.38s / 0.3），
  落下不回弹（0.26s / 0）。停着的时候谁都不缩放，端头是正圆。
- **透镜在字上面**（z 3，悬停透镜在字底下）：它要折射的就是底下的字。里面不铺色、不模糊，只挂折射（§4.7 最后一行）：
  边上把字放大、弯折、泛一点彩边，正中原样。
- **只平移、绝不缩放**：透镜的位置写在 `transform: translate3d()` 上，大小写在 `width` / `height` 上，从不 `scale()`。
  中心永远是滑块中心（字在正中）；比这一行（滑块高 + 上下内边距）高两成、伸出上下沿；比项左右各宽 7px；
  停在两端时两边对称收窄、不伸出轨道。拖的时候宽度跟着手指下的滑块在相邻两项之间过渡（只挪九宫格，§4.5）；
  飞的时候是终点那一项的宽度，一路只平移。
- **按在没选中的项上**（iOS 26：手指按在哪一项，玻璃就到哪一项底下）：滑块马上浮起、飞到手指下面；
  选不选还是交给页面——不动就松手，浏览器的 click 照常落在那个按钮上；页面一时没改过来（异步处理），滑块在那儿等 1.2 秒再回去。
- **拖**：按住任一项、横向动 5px 以上就开始拖。滑块的目标跟着手指，滑块用一根很快、不回弹的弹簧（0.12s）去追——
  直接写位置的话，按下后马上拖，滑块会从飞到一半的地方一下跳到手指下面。字的选中样子跟着玻璃走（见下面「玻璃底下的字」）；
  松手落到最近的一项。速度做一阶低通（系数 0.35），快速一甩（≥ 0.6 px/ms，松手前 90ms 内还在动）往甩的方向**最多再走一格**。
- **橡皮筋**：拖过第一项 / 最后一项的中心时，整条按 `max · (1 − 1 / (越界 / max × 0.55 + 1))` 被拉长——越拉越费劲，
  永远到不了上限 `max = min(18px, 轨道宽 × 5%)`；钉住另一端，横向拉长时竖向收 35%，看着是同一团东西被拉长。
  松手用一根回弹 0.5 的弹簧弹回，冲过头压扁一下再停。
- **甩**：大力一甩，整条朝甩的方向形变 `min(3.5%, 速度 × 0.012)` 再回弹（给橡皮筋弹簧一个初速度；阻尼比 0.5 的弹簧最远到
  0.546 × 初速度 / ω，反推初速度）。
- **点别的项、键盘换选中**：滑块**浮着、整块飞过去**——浮着的时候两条边用同一根弹簧（0.40s / 回弹 0.28），不再前沿先到、
  后沿后到：透镜跟着滑块中心走，后沿一拖，透镜就远远落在后面。**飞的路上只有这一块玻璃**：按下那一刻悬停透镜立刻撤掉、
  飞完之前不再出来（它会先到终点那一项底下，看着就像选中「跳」过去了）；**选中色跟着玻璃走**：被玻璃盖住的项依次
  变成选中的样子（见下面「玻璃底下的字」），页面已经标成选中的终点那一项等玻璃到了才亮，路过的项依次亮一下。
  **完全浮起来、而且中心到了**才落下——
  相邻两项之间 0.2 秒就到，只等「中心到了」的话透镜才浮起八九成就落下，一闪而过，看不出玻璃从一项滑到另一项。
  浮起时平胶囊很快化开（浮起两成五就看不见）：飞的时候它被液态拉长，留着就是两层。
  页面从外面改的选中（不是这 0.7 秒里用户点的、按的）只平移过去，不浮起。
- **玻璃底下的字**（iOS 26 按住标签栏时最显眼的那一下）：被玻璃盖住多少，字就放大多少、变粗多少、换成选中色多少。
  「盖住多少」`z` 按滑块此刻的两条边和每一项的位置算（重叠宽度 ÷ 项宽，0–1），和玻璃的移动是同一个连续量——
  飞过两项之间时，一枚字一边缩回、一边褪色，另一枚一边放大、一边上色，不是到了中点「啪」地换一枚。
  - 放大 = `1 + --lg-seg-mag × z × 浮起程度`：只有浮起的透镜才放大，落下时字跟着玻璃一起缩回；浮起的回弹也带到字上。
    默认一行字的分段开关 0.12、玻璃导航条 0.18（图标和字都在里面，透镜也大）。写在独立的 `scale` 属性上，不碰 `transform`
    （悬停透镜的放大写在那里，两边互不覆盖）。透镜在字上面，放大以后的字再被透镜的边弯折、泛彩边——两样叠起来才像 iOS。
  - 颜色和粗细由样式表按 `--lg-z` 算：`color-mix()` 在普通色和选中色之间按 `z` 混，`font-weight` 按 `z` 从普通插到粗体
    （可变字体是连续的，静态字体按就近的字重分几档）；浏览器不认 `color-mix()` 时退回「离玻璃最近的那一项整枚换」（`data-lg-near`）。
    拖动、飞的时候颜色过渡关掉：值逐帧在变，再叠 0.2 秒的过渡，字就落在玻璃后面。
  - 这些只在 `data-lg-ink` 挂着时生效：拖着、浮着飞，以及「替用户选了、页面还没改过来」的那一段。最后这段不能漏：
    玻璃落定、页面的 click 还没处理完的那一两帧里，样式表会按页面的旧选中画，原来那一项一下变粗变色（pitfalls.md 第 39 条）。
  - 「精简」拖动时不浮起，字不放大，但颜色和粗细照样跟着滑块走。
- **选中由页面决定**：拖完松手，脚本替用户「点」一下落到的那一项（`element.click()`），页面的点击处理照常运行，
  改不改 `aria-pressed` 由页面决定；页面没接受，滑块回到真正选中的那一项。紧跟在拖动后面、浏览器自己补的那一下 click
  （`isTrusted` 为真）被吞掉，不然它会把选中又点回原处。**指针捕获等动起来才设**：只按一下不动的话，click 还落在按钮上。
- **粗体预留宽度**：选中项是粗体，按钮宽度按粗体留（脚本把字写进 `data-lg-label`，样式表在 `::after` 里放一份隐形的粗体撑宽），
  选中变粗、拖动时「最近那一项」变粗，都不会把旁边的项挤开。按钮里有图标之类的元素时不动它的排版。
- **玻璃导航条**（`.lg-glass.lg-seg.lg-seg--glass`，iOS 26 的标签栏）：整条是一块浮在内容上面的玻璃，项是图标在上、字在下、
  等宽铺满（宽度不随字变），选中项是一块平胶囊 + 主色、加粗的图标和字（没选中的 500、选中的 650），拖动中被玻璃盖住的那一项
  放大、加粗、换成主色。透镜在这里比一行字的分段开关大得多
  （约 70px 高），放大、弯折、彩边都看得清。整条的边默认不折射：条只有 58px 高，边上那一圈占得太多，实测是一圈发灰的厚边。
- **分档**：「完整」才浮起、拉长、回弹；只在 Chromium 上、而且和页面之间没有背景根（§4.10）时才有那块透镜——
  不能折射时一块清玻璃只是个空框，这时滑块自己放大一点（横 5%、竖 10%）就是「按住了」。
  「精简」和「减少动态效果」照样能拖（这是功能），但滑块直接到位；「关闭」没有滑块，也就不能拖。

## 9. 分档与自动降级

用户看到的是三档开关，写在 `<html data-lg-mode>`；**三档必须一眼分得出来**，所以按用户看得见、摸得着的东西分：

| 档 | 看起来 | 动起来 |
|---|---|---|
| **完整** | 半透明玻璃；Chromium 上背后有内容的玻璃边缘折射；HDR 屏上有高光 | 透镜与滑块流过去，经过的项微微放大、跟手，按下像果冻；弹出层从上方长出来 |
| **精简** | 面板不透明、不折射，高光环还在 | 透镜与滑块**直接到位**，不放大、不跟手、不弹出；按钮不浮起 |
| **关闭** | 实色面板、没有高光环与柔光 | 没有透镜、滑块、指尖光与玻璃提示；悬停叠一层薄暗，选中项用自己的底色 |

材质另写在 `<html data-lg-tier>`：

| 档 | 效果 | 条件（从上往下，先满足先定） |
|---|---|---|
| l0 实色 | 形状、投影还在，只是不透 | 精简、关闭；浏览器不支持背景模糊；系统「减少透明度」 |
| l1 模糊 | 模糊 + 高光环 | 完整但不是 Chromium；自动档下显卡是软件渲染，或动画掉帧 |
| l2 折射 | 再加边缘折射 | 其余情况 |
| l3 HDR | 再加 HDR 高光 | l2 且 `(dynamic-range: high)` |

- **不闪**：`<head>` 里一段内联脚本在样式生效前按记住的档位先写好 `data-lg-mode`，再定临时材质档
  （精简、关闭 = l0，完整 / 自动 = l1）；脚本加载后再升到 l2 / l3。l1 所有浏览器都画得出来，从它升级看不出跳变。
- **自动档**（没动过开关）：按钮上显示「完整」，只在材质上自己降（先不折射），动画照常。
  - 显卡检测：建一个 WebGL 上下文，读 `WEBGL_debug_renderer_info` 的显卡名，匹配
    `SwiftShader | llvmpipe | softpipe | Software | Basic Render | Microsoft Basic`；拿不到 WebGL 也算软件渲染。
    远程桌面、虚拟机、没装显卡驱动时都是这样，折射每帧都靠 CPU 算，会卡。
  - 掉帧检测：透镜 / 滑块动画期间攒够 45 帧，中位数超过 30ms（不到 33 帧每秒）就先不折射，本次会话记住（`sessionStorage`）。
    用中位数不用平均数，刚加载、大表格刚画完那几帧的卡顿不会误判。
- **手动档**：点「完整」就是明确要，照开折射（清掉掉帧记录）；「精简」「关闭」照办。
- 点开关当场弹一句这一档是什么样；鼠标停在开关上，提示里写着现在实际是哪一档、为什么。
- 跟着系统变：`dynamic-range`（窗口拖到另一块屏）、「减少透明度」「减少动态效果」变了都即时生效。

## 10. 背景根（Backdrop Root）

W3C Filter Effects Level 2 规定：一个元素的祖先如果带 `filter`、`opacity < 1`、`mask`、`clip-path`、
`backdrop-filter`、`mix-blend-mode`（或 `will-change` 了这些），这个祖先就是它的**背景根**。
`backdrop-filter` 只看得见背景根里面画过的东西——看不见背景根外面的页面。

表现：玻璃在淡入动画的那几百毫秒里突然变亮 / 变空，动画结束时「跳」回来；或者弹出层里的玻璃是一片灰。
由此来的几条硬规矩：

- 弹出动画只动 `transform`，**不做淡入**。
- 透镜的淡入淡出只改子层的 `opacity`，外层只改 `transform`。
- 遮罩只调暗、**不模糊**：遮罩一带 `backdrop-filter`，里面的面板就只能采到遮罩。
- 不要给玻璃的任何祖先加 `opacity` 动画、`filter`、`mask`。
- 挂了 `url()` 位移滤镜的玻璃隔着背景根时不只是采不到背景，还会画成一块发暗的方块（§4.10）——脚本检测到就不开折射。
  这也是为什么面板的毛玻璃画在 `::before` 上而不是宿主上：宿主自己带 `backdrop-filter` 的话，它里面的透镜就隔着背景根了。
