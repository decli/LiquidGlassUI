# 设计决策记录

现在这套样子是怎么来的：从初稿到定稿，每一轮评审或用户反馈指出了什么、原因是什么、怎么改的、能推广成什么结论。
用户要改风格、或者你想「改回」某个做法之前，先看这里——多半已经试过了。

## 1. 初稿

先在设计画布上做了一版：控制层全部是玻璃，页面底垫一层满屏的点阵（18px 间距的小圆点）给玻璃「有东西可折」，
登录卡背后铺一面大字、卡片做成几乎不模糊的清玻璃，边缘把字折弯，还加了色散（红绿蓝各折一遍，边上一点彩边）。
每块玻璃的边宽、隆起、厚度一块块调过。然后照着它实现到真实页面上。

## 2. 第一轮：设计评审（交互一致性）

| 现象 | 原因 | 改法 |
|---|---|---|
| 「鼠标放在某些菜单上有玻璃效果，一些地方没有，整体很割裂」 | 只给侧栏做了玻璃悬停，别处还是老的变色 | 所有能悬停的项统一成**一颗会流动的透镜**；每块面板一颗 |
| 页头两颗并排的玻璃胶囊一深一浅 | 一颗是 `<button>`，浏览器默认的浅灰底垫在玻璃下面 | 玻璃宿主一律 `background: transparent`；并排的胶囊用同一个类 |
| 透镜在上下相邻的菜单项之间移动时字在闪 | 移动中透镜在变形，折射贴图却是停稳时的尺寸；透镜又盖在字上 | 停稳才淡入折射；透镜垫到字底下 |
| 透镜落在蓝色选中项上时把它洗白，边缘有锯齿 | 白玻璃叠在蓝上；位移滤镜是最近邻取样 | 落在选中项上时底色退到几乎透明、不开折射 |
| 命令面板里危险页的条目被画成三条红色按钮 | 条目带着 `.danger` 类，吃到了危险按钮的样式 | 单独写回；本套件所有类都带 `lg-` 前缀 |
| 宽列表项悬停时左边的字往左跳 | 放大以中心为原点，宽项放大 2% 左边就跳 5px | 宽列表项 ≤ 1.5%，表格行 0 |
| 选中滑块从第一项跳到最后一项，中途是一根长柱子 | 后沿用慢弹簧、没有上限 | 拉长上限：比落点那一项最多长 44px（横向 56px） |

**结论**：一致比炫更重要。同一类交互只用一种反馈；「有的地方有、有的地方没有」比「都没有」更糟。

## 3. 第二轮：上线后「太花」「开关没反应」

**「点状背景充斥整个屏幕，有点丑。」**
点阵是为了让玻璃「有东西可折」垫的，但页面是数据工具，一屏几十行字，底纹再轻也是噪声。
→ 页面底回到纯色。代价是侧栏、页头这些背后只有页面底的玻璃看不出折射，于是**折射只留给背后真有内容的几块**
（弹出菜单、命令面板盖在正文上；底部保存条底下滚着表单）。顺带的好处：侧栏背后不变，滚动时浏览器不用每帧重算它的模糊。

**「精简、关闭按钮似乎没反应，刷新后也是依旧有完整的玻璃特效。」**
当时的定义是「精简 = 去掉折射」「关闭 = 去掉透明」，形状、高光、透镜、动画全都还在；页面底又是纯色，三档逐像素比只有 0.2% 的像素不同。
而用户在远程桌面上，自动档本来就是「只模糊」，点「精简」完全没有变化。
→ 三档按**看得见、摸得着**的东西重新定义：精简 = 面板实色 + 透镜与滑块直接到位、不放大不跟手不弹出；
关闭 = 连透镜、滑块、高光环、柔光一起撤掉，悬停退回薄暗。点了当场弹一句「这一档是什么样」。
另外发现「关闭」时开关自己跟着消失了（显示条件和「关闭」撤掉的是同一个属性），改成另用 `data-lg-js` 判断。

**结论**：装饰性的底纹不要铺满屏；开关的每一档必须肉眼分得出来，而且要当场给反馈——用截图逐像素比一比再上线。

## 4. 第三轮：同一个功能两个入口

**「左侧菜单有切换环境的卡片，右上角也有同样的菜单，重复了。左侧这个相比右上角有点突兀。」**
→ 只留页头右上角的胶囊：人看的是页头；它在每一页都看得见；危险页上它还能染红、写「将改动」。侧栏只管导航。

**结论**：一个功能一个入口。两个入口不是「更方便」，而是让人怀疑它们是不是同一个东西。

## 5. 第四轮：提示文案与侧栏层级

**「退出登录后，那个『已退出』的文案有点丑。」**
自己点的「退出」回到登录页时，被放进了红色报错框（还带一道贴着圆角弯过去的左侧竖条）——像出了错。
→ 分成两种话：「为什么回到这里」的说明（已退出、会话过期）用灰色，挂在输入框上方，开始打字就收掉；
真出错（口令不对）才用红色，挂在按钮下面。都是「图标 + 一句话」，去掉竖条。

顺带查出一个真缺陷：输错口令被说成「登录已过期，请重新登录」。公共请求函数把**登录接口本身**的 401 也当成了会话过期。
→ 登录接口的 401 就是「口令不对」，只有别的接口的 401 才是过期。

**「一级菜单和下面的子菜单字号差距比较大，不太协调。」**
组标题比菜单项小，却更黑更粗，外加一条通栏分隔线，两层在抢。
→ 第一版：组标题改成次要色的小标签（12px、半粗、灰），去掉分隔线。用户接受了字号，但觉得「还是有点别扭」，见第七轮。

**结论**：说明和报错是两种语气，颜色要分开；「谁是标题」靠位置和留白表达，不靠加粗加黑。

## 6. 第五轮：登录页

**「去掉登录页背后的数字背景墙。」**
理由同第二轮：满屏的字是噪声。→ 登录卡背后回到纯色，卡片改用弹出层那种更实的玻璃（78%）；
既然背后没东西可折，折射和色散一起删掉。

**结论**：玻璃显不显得出来，靠的是真内容从它底下经过，而不是专门给它铺一层花纹。

## 7. 第六轮：按钮悬停不统一

**「『填个示例』『清空』这俩按钮鼠标划过没有动画效果，和其他按钮风格不统一。」**
白色次按钮悬停时指尖光是白光，打在白按钮上等于没打；而蓝色主按钮上看得很清楚。
→ 主 / 次 / 危险按钮与页头胶囊统一成同一套动作：浮起 1px（弹簧曲线）+ 投影加深 + 指尖光；白按钮的指尖光带 13% 主色。
按下缩到 96.5%——顺带发现按下的规则写在悬停前面，按下时还浮着；挪到后面。

**结论**：同一类控件的反馈要「同一套动作」，颜色可以不同，动作不能不同；每种底色上都要确认反馈看得见。

## 8. 第七轮：侧栏分组（调研后定稿）

**「这种菜单设计看着还是有点别扭，每次要看很久才知道这个菜单属于哪个标签。业界有类似可以借鉴的案例吗？」**

诊断（为什么要看很久）：

- 组标题和上下两组的距离差不多，看不出它属于下面那组；
- 每个菜单项前面一个灰色圆形图标底，一列圆点连成一根贯穿所有组的竖柱，把分组冲散了；
- 收起箭头挂在一整行之外的最右边，看不出它是这一组的。

调研：Apple HIG *Sidebars*（最多两级；用分组；标签简短；用符号图标、可带强调色）、iPadOS「设置」（每组一块圆角底板）、
macOS Finder / Mail 侧栏（只靠小标题和留白分组）。

比较了两个方案（`design/sidebar-evolution.png`）：

| 方案 | 做法 | 结果 |
|---|---|---|
| A · macOS 式 | 去掉圆形图标底；组标题小灰字；组间距拉到 20px、组标题到菜单 4px；只靠留白分组 | 比改前好，但留白要足够大才分得开，侧栏变长 |
| **B · iPadOS 式（定稿）** | 在 A 的基础上，每组菜单项垫一块圆角底板（危险组带一点红）；组间距 14px | 一眼看出一项属于哪一组；底板在折叠成图标轨时也能分组 |

定稿细节：组标题 12px 半粗灰、紧贴底板（4px）；箭头紧跟组名；菜单项 32px、16px 线性图标、不垫底色；
底板圆角 14 = 菜单项圆角 10 + 内边距 4（同心）；快捷键数字平时隐藏，鼠标进了菜单才浮出来；
透镜放大量从 3% 降到 2.5%（项在底板里，放大多了会顶出底板）。

**结论**：分组靠「容器」比靠「标题」更快被看懂；同心圆角让嵌套的形状看起来是一体的；平时用不着的信息（快捷键）藏起来。

## 9. 第八轮：对照 ZeppBridge 重做折射，给分段开关加上按住浮起

**「ZeppBridge（v3 分支）用 HTML5 + Tauri 套壳实现的 Liquid Glass 非常逼真，仔细读它的文档和源码，改进我们的方案和效果。」**

ZeppBridge 是一个桌面应用，照 iOS 26 App Store 标签栏的录屏逐帧核对，把玻璃改了五版（`src/lib/glassLens.ts`、
`src/components/SegmentTrack.vue`、`src/lib/segmentGlass.ts`、`scripts/assets/build-glass-lens-maps.py` 与每一版的提交说明）。
读下来，它比我们逼真在两处：边缘的光学模型，和「按住浮起」这个交互。对照后查出我们自己的问题：

| 现象 | 原因 | 改法 |
|---|---|---|
| 折射看着「弱」：一大圈斜面几乎不动，只有最外沿一两个像素在变 | 斯涅尔定律 + 凸超椭圆剖面算出的位移全挤在最外两三个像素里 | 换成 `D(s) = 0.45·b·(1 − s/b)²`：往里取样、越靠边越大，边上拉开约十倍，平滑落回原样 |
| 玻璃边上的字被画两遍、夹一道镜像（放大看演示页那颗玻璃的上沿最明显） | 同一条曲线在最外沿 D′ < −1，贴图折叠了；我们的自检只验了「位移单调减小」，没验「取样位置单调」 | 新曲线处处 1 + D′ ≥ 0.1；自检改成验取样位置单调 |
| 放大的边上一级级台阶 | 位移滤镜最近邻取样，拉开越多台阶越明显 | 边上按位移大小叠一层模糊（m^1.6）、一层很淡的乳白（散射）、红绿蓝三路略不同的位移（色散）；中间直接用原图 |
| 拖窗口时折射先消失、停手 140ms 才回来；悬停透镜只能停稳才折射 | 每个尺寸重画一整张贴图 | 贴图切九宫格（ZeppBridge 是胶囊的端帽 + 中段，我们推广到任意圆角），尺寸变了只挪八块 |
| 分段开关只会「流」，按住没有任何变化 | 没做 | 照 iOS 26 标签栏：按住选中项浮起成一块盖在字上面的清玻璃透镜，能拖、拖过两端像橡皮筋、甩一下会形变；点别的项浮着飞过去 |
| 选中项变粗时把旁边的项挤开 1–2px（英文标签上量得到；中文字粗细同宽，看不出来） | 按钮按内容收紧，粗体更宽 | 按粗体留宽度（隐形的粗体 `::after`） |

照搬之前先想清楚的几条（也是 ZeppBridge 自己踩过、写在提交说明里的）：

- **往外取样是错的**。它第三版为了「把外面的东西折进来」往外取样，结果是缩小、字被画两遍，第四版改回往里取样。我们直接用第四、五版的结论。
- **会折射的元素只平移、不缩放**。它第四版发现透镜尺寸每帧变、还带缩放，又糊又卡；第五版透镜只平移，尺寸跟着项宽走、只挪贴图。
  我们的悬停透镜要做水滴形变，所以它仍然只在停稳时折射；新加的浮起透镜一路只平移，所以一路都在折射。
- **隔着背景根的透镜是一块暗方块**。它 2026-10 实测：祖先带 `backdrop-filter` / `filter` / `mask` 时，挂 `url()` 滤镜的透镜不只采不到背景，
  输出还会把原图换掉。我们的 `.lg-glass` 本来就把毛玻璃画在 `::before` 上，所以侧栏、工具条里的分段开关照样能浮起；
  别的情况由脚本检测、检测到就不开折射。
- **选中由页面决定**。它是 Vue 组件，自己管值；我们不碰业务，所以拖完松手是「替用户点一下」落到的那一项（`element.click()`），
  页面照常处理；浏览器紧跟着补的那一下 click 要吞掉，不然选中又被点回原处。
- **没照搬的**：它的折射默认开、只用 `?lens=0` 关；我们仍然走三档 + 自动降级（软件渲染、掉帧时先不折射）。
  它的位移图是构建时生成的 PNG 文件（因为它的 CSP 不许 `data:` 图片）；我们是零构建的单文件，仍然在运行时用 `<canvas>` 画、用 `data:` 挂，
  只是现在每种圆角 × 边宽只画一次。

校验：`shoot.mjs` 多了两项——折射校验（把折射那一步换成 `blur(0px)` 前后各拍一张，玻璃正中逐像素一样、外圈约 15% 的像素在弯）、
分段开关校验（按住浮起、只按不动不换选中、拖着换选中、甩、橡皮筋、点别的项浮着飞、精简档照样能拖）。截图见 `design/lift@2x.png`。

**结论**：先找一个比自己更逼真的实现，逐条问「它为什么这样」，再回头查自己——这一轮查出的折叠，是我们自己的自检漏掉的。
物理上「对」的模型不一定看着像，要以录屏逐帧对出来的样子为准；能验的就写进校验脚本。

## 10. 总结：可以直接带走的结论

1. 玻璃只给控制层；内容层是实心的厚玻璃，用同一种高光语言。
2. 页面底用纯色，不为玻璃铺底纹；折射只给背后真有内容的玻璃。
3. 同一类交互只用一种反馈（透镜 / 浮起 + 指尖光），同一类选择只用一种控件（凹槽 + 滑块）。
4. 一个功能一个入口。
5. 设置开关的每一档都要肉眼分得出来，点了当场给反馈。
6. 说明（灰）和报错（红）分开；登录接口的失败不是「会话过期」。
7. 谁属于谁，靠位置、留白和容器表达，不靠加粗加黑。
8. 每种底色上都要确认反馈看得见（白上白光等于没有）。
9. 弹出只动 transform，永远不淡入；玻璃的祖先不加 opacity / filter / mask。
10. 降级不能坏功能：老浏览器、软件渲染、减少动态效果、减少透明度，每一种都要真机看一遍。
11. 玻璃边是放大 + 模糊 + 散射，正中原样；位移曲线要验「取样位置单调」，不是只验「位移单调」。
12. 会折射的东西只平移、不缩放；尺寸变了只挪贴图、不重画。
13. 交互不碰业务：要换选中，就替用户点一下，让页面自己决定。
